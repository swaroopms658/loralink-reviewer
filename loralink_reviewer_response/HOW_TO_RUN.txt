LoraLink reviewer response (Abhay & Nikhil) - Colab Free Tier package.

Repo (public): https://github.com/swaroopms658/loralink-reviewer
The notebooks git clone the full patched repo to get main.py and the other patched
sources; this zip is the loralink_reviewer_response/ package only.

1. Open notebooks/00_setup_smoke.ipynb in Colab. Runtime > Change runtime type > T4 GPU.
   Runtime > Run all. Must print SMOKE PASS before you fan out (~10 min).
2. Run 01-05 across separate Google accounts (see README "Per-notebook run guide" for
   shard assignments). Edit only ACCOUNT_TAG and SHARD in cell 3. Each notebook
   downloads results_*.csv + results_*.summary.csv.
3. Put all downloaded CSVs in one folder, open notebooks/99_aggregate_report.ipynb,
   upload them -> tables, plots, RESPONSE_ABHAY_NIKHIL.filled.md.

IF THE PACKAGE IS UPDATED MID-CAMPAIGN, two separate things go stale:

  1. THE NOTEBOOK. Cell 1 re-clones the repo but does NOT change the .ipynb you
     already have open -- that JSON is whatever you opened. Re-open it from
     GitHub.
  2. THE IMPORTED MODULES. A kernel that already imported cluster_launch,
     pipeline_engine etc. keeps the OLD code in sys.modules; re-cloning the
     files does not reload them. Cell 1 now drops those modules after cloning,
     so re-running cell 1 is enough -- but you must actually RE-RUN CELL 1, not
     just cell 4.

Both failures look identical to "the fix didn't work", because everything else
behaves normally. Cell 1 prints the commit hash in use -- check it matches the
latest before trusting a run.
